# 架构

目标是可靠索引答案、逐步显示绘制过程与查看局部，不模拟旧课件的整个运行环境。

Windows 的 React 界面只先读取轻量 `index/catalog.json`，建立章节、页码、题号和别名索引。选题后读取对应文档，确定分支、步骤及热点；绘图通过 WebView2 消息调用 C# 引擎，重放场景中的 WMF、几何、文字及原有位图。

屏幕显示的 PNG 是本次绘制缓冲。缩放和重画仍基于保留的场景及矢量素材；源位图仍是位图。绘图任务只保留最新待执行请求，完成和解码后替换画面，避免拖动进度条时加载遮罩闪烁。缓存有预算，不代表整个进程内存上限。

Android 使用相同目录/题目概念，读取转换出的 SVG，通过 AndroidSVG 和 Canvas/Picture 绘制；双指缩放后重放矢量。GIF 与视频由各自媒体组件处理。全屏横屏与竖屏共用题目和步骤状态。

热点属于某一帧的局部链接，不是与题目平级的目录项目。详图有返回栈；翻题始终沿当前筛选后的题目顺序，边界使用短提示。

Windows 的现有解包数据放在 `content/windows`，Android 的对应 SVG、索引与媒体放在 `apps/android/app/src/main/assets/content`。两端默认使用完整题库，无需本地提取记录或旧程序。数据导出器与核验脚本位于各应用目录，`scripts/verify_content.py` 检查两端题目、步骤、热点和媒体引用。原始提取记录、REA/DSH 工作环境与签名私钥不入库；`samples/generate_demo.py` 仍可生成独立原创小示例。
